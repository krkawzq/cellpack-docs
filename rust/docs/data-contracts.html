Data contracts ​

CellPack checks arguments at API entry points and then trusts the data inside its per-record loops. A broken argument returns an Err. Broken trusted data is undefined behavior: out-of-bounds reads and writes, a segfault, or silently wrong output, with no error returned.

This page lists what is trusted, who supplies it, and how to stay inside the contract. For exact shapes, dtypes and identity spaces, see the shape and type reference. For callbacks, see ABI.

Where the boundary lies ​

Release builds drop the trusted-side checks entirely. Debug builds keep them as debug_assert!, so a violation panics there instead of corrupting memory. No cargo feature adds checks; the only switch is debug-assertions.

In-memory matrices are validated ​

Everything that enters the codec from memory is checked before encoding: n_genes in 1..2^31, value widths of 1, 2, 4 or 8 bytes, monotone row offsets that stay inside the index and value arrays, and indices that are strictly ascending and below n_genes. The checks run as part of the encode pass, so there is no separate validation call to make:

rs
// Encoders validate every in-memory matrix: here row 0 lists column 3
// before column 1.
let indptr = [0u64, 2];
let indices = [3u32, 1];
let values: Vec<u8> = [1.0f32, 2.0].iter().flat_map(|v| v.to_le_bytes()).collect();
let unsorted = CsrRef {
    n_genes: 4,
    value_width: 4,
    indptr: &indptr,
    indices: Indices::U32(&indices),
    data: &values,
};
let options = common::options().encode;
let encoded = chunk_sizes(&unsorted, Rows::All, &options).and_then(|sizes| {
    let mut out = vec![0u8; sizes.output_bytes];
    let mut workspace = vec![0u64; sizes.workspace_words];
    encode_chunk(&unsorted, Rows::All, &options, &mut out, &mut workspace)
});
assert!(matches!(encoded, Err(cellpack::Error::InvalidInput(_))));

Column maps and schemas are checked when they are registered, and access ids when they are used:

rs
// Column maps are checked when a file is registered: two source columns
// may not land on the same standard id.
let path = common::fixture()?;
let mut builder = DataSourceBuilder::new(4, 4096)?.direct_io(false);
assert!(builder.add_cpk(&path, &[0, 0, 2, 3]).is_err());
builder.add_cpk(&path, &[0, 1, 2, 3])?;
rs
// Cell ids are checked before they index the catalog.
let schema = OutputSchema::dense(1, vec![0, 1, 2, 3], Dtype::F32)?;
let config = LoaderConfig {
    workers: 1,
    backend: IoBackend::Pread,
    slot_cells: 2,
    ..LoaderConfig::default()
};
let loader = Loader::new(Arc::new(builder.build()?), vec![schema], config)?;
let ring = Arc::new(Ring::allocate(loader.ring_layout(2, 1))?);
let accesses = [0u32, 9];
match loader.prepare(&accesses, ring, Planning::None) {
    Err(loader::Error::Access { position, cell }) => assert_eq!((position, cell), (1, 9)),
    Err(other) => return Err(other.into()),
    Ok(_) => panic!("cell 9 is outside a four-cell source"),
}

The complete program is docs/cellpack/examples/contracts.rs:

sh
cargo run --locked --manifest-path docs/cellpack/examples/Cargo.toml \
  --bin contracts -- tmp/cellpack-guide/contracts

Record bytes are trusted ​

A .cpk stream protects its superblock and directory with a hash, and every chunk's metadata is parsed and validated when a CpkFile opens it or a DataSourceBuilder registers it. Record bytes are not. The decoders assume each record is exactly what the encoder wrote for that chunk: section lengths inside the record, ids ascending and below the dimension count, dictionary ranks below the dictionary size, element counts within the chunk maxima.

A damaged or forged record therefore reads and writes past the record, the decode workspace or the output row. The decoded element count is compared with the metadata afterwards and reported as CorruptRecord, but by then the damage is done; treat that error as a symptom, not a guard.

In practice:

  • Read only streams written by CpkWriter and stored where they cannot be modified by untrusted parties. CellPack is not a validator for files from untrusted sources.
  • Keep files immutable while selections, data sources, loaders and plans use them. Rewriting a file in place under a running loader is the same as handing it corrupt records.
  • CpkWriter::append_packed copies an externally packed chunk after parsing its metadata only. Its records are trusted from then on; produce such chunks only with scans::encode_chunk and scans::pack_chunk.
  • format::record_nnz reads only the header and checks it, so it is safe on any bytes; matching the metadata count does not make the rest of the record valid.

To vet a file of uncertain origin, read it completely once in a build with debug assertions enabled. Violations then panic at the first inconsistency instead of corrupting memory:

toml
# Cargo.toml of the application
[profile.validate]
inherits = "release"
debug-assertions = true
sh
cargo run --profile validate --bin check-files -- data/*.cpk

This is a diagnostic, not a security boundary: it relies on the same parser and costs a full decode.

Low-level codec calls must keep records with their chunk ​

The scans functions take metadata, tables and record bytes as separate arguments. They check that the tables match the metadata (TablesMismatch) and that outputs and workspace are large enough. They cannot check that a record came from the chunk the metadata describes. Derive all three from the same packed chunk:

rust
let meta = parse_meta(&packed)?;                 // validated metadata
let tables = decode_tables(&meta)?;              // checked against meta
let records = meta.records_of(&packed)?;         // records of this chunk
let mut workspace = vec![0u64; decode_workspace_words(&meta)];
decode_csr(&meta, &tables, records, Rows::All, IdSpace::Source,
           &mut indptr, &mut indices, &mut values, &mut workspace)?;

Mixing metadata from one chunk with records from another, or decoding a record slice cut at the wrong offset, is undefined behavior even though every argument type checks.

Parts views borrow the workspace, record and metadata they were decoded from. Consume a Parts before reusing any of them; the borrow checker enforces this for safe code, but raw pointers derived from a Parts are not tracked.

Positions passed back in ​

Two interfaces accept positions that address elements of an already decoded row:

CallRequirement
scans::map_parts_at(parts, positions, …), Mapper::map_parts_atEvery positions[i] < parts.elements()
Partial-row resolve(row, positions, count, …) in a process functionEvery positions[i] < nnz; output arrays hold count entries

Both check every position before mapping: map_parts_at returns InvalidInput and resolve returns a nonzero status, which a process function should pass on. Positions may repeat and need not be sorted. Compute them from the row's own element count, never from a different row or a stale value, so that the check never fires in a correct program:

rust
let n = parts.elements() as u32;
let picks: Vec<u32> = sample.iter().map(|&p| p % n).collect(); // always in range
mapper.map_parts_at(&parts, &picks, &map, &dict, &modes, &mut cols, &mut vals)?;

Access sequences must be pure ​

Accesses is a safe trait, but its contract is stronger than its signature: fill(start, out) must return the same cells for the same accesses on every call. Workers, the online planner and plan verification all call it, from several threads, out of order and more than once.

The loader checks every returned id against the source (Error::Access). Under a fixed or online plan, each plan entry also records the cell it was built for, and a worker whose own fill disagrees stops the run with Error::Plan before following the entry's cache frames. Without a plan there is nothing to compare against: a nondeterministic sequence silently produces batches that differ from the order the application intended.

Derive randomness from the position instead of from a mutable generator:

rust
// Wrong: state advances with each call, so repeated ranges differ.
struct Sampled { rng: Mutex<StdRng>, cells: u32, len: u64 }

// Right: a pure function of (seed, index).
struct Sampled { seed: u64, cells: u32, len: u64 }

impl Accesses for Sampled {
    fn len(&self) -> u64 { self.len }
    fn fill(&self, start: u64, out: &mut [CellId]) -> loader::Result<()> {
        for (i, cell) in out.iter_mut().enumerate() {
            let h = splitmix64(self.seed ^ (start + i as u64));
            *cell = (h % self.cells as u64) as CellId;
        }
        Ok(())
    }
}

Shuffle, Replicate, Offset, SliceAccesses and stored slices satisfy this contract. Native sequences (ExternAccesses, ExternCorpusAccesses) carry the same requirement plus the write-bound and lifetime rules in ABI.

External ring memory ​

Ring::allocate owns its memory and needs no care. The constructors over caller memory are unsafe:

ConstructorCheckedTrusted
Ring::init(ptr, len, layout)Non-null, 4096-byte aligned, len ≥ layout.bytes()Memory outlives the ring and every batch lease; there is no owner handle
Ring::with_buffer(data, len, layout, owner)Alignment, data_min_bytes ≤ len ≤ data_bytesowner keeps data allocated; nothing else writes slots being filled
Ring::init_regions(control, …, data, …, owner)Control 64-byte aligned, sizes, regions disjointExclusive during initialization; every process follows the slot protocol
Ring::attach(ptr, len)64-byte alignment, size, header magic and version, re-derived offsetsThe mapping stays valid; other processes touch it only through the protocol
Ring::attach_regions(control, …, data, …, owner)As init_regions, plus headerAs above

REGION_ALIGN is 64 and SLOT_ALIGN is 4096. Use RingLayout::bytes, control_bytes, data_bytes and data_min_bytes to size allocations, and pass data arrays aligned to 64 bytes so that every schema region inside a slot is 64-byte aligned. For cross-process rings, map control memory MAP_SHARED: waits use shared futexes.

A batch region stays valid while its lease is held. An asynchronous device copy reads the region until it completes, so release the lease only after the copy has finished.

Checklist ​

Before handing data to CellPack:

  • [ ] Files come from CpkWriter and are immutable while in use.
  • [ ] Records, metadata and tables passed to scans come from the same chunk.
  • [ ] Accesses::fill is a pure function of the access index.
  • [ ] Native callbacks satisfy the ABI obligations.
  • [ ] External ring memory is sized from RingLayout, aligned, and outlives every lease.
  • [ ] Data of uncertain origin has been read once under debug-assertions = true.

API: Error, loader::Error, Accesses, Ring, RingLayout, Mapper.
