Statistics, profiling, and cost models ​

Always-on counters ​

Every run returns RunStats, even when profiling is disabled.

FieldInterpretation
elapsedWorker and plan-thread wall time after setup
setup_elapsedFrame sizing and shared-state setup before execution
countersAccesses, decoded rows, hits, admissions, bytes, and stalls
ioRequest counts, requested and returned bytes, request-size buckets
peak_spanLargest access lead past the execution frontier
cache_bytes, private_bytesFrame reservations
outputsPer-schema access, decode, row-hit, and process counts
profileTiming report when enabled
onlineOnline compiler statistics when used

counters.accesses counts one delivery per schema per position. It is not the number of distinct cells or batches. Multiple schemas of one position can share one decode. page_hits count page uses served by cached frames; row_hits refer to decoded input rows.

Live Run::snapshot() exposes published counters. Use final statistics after successful completion for reporting; in-flight snapshots can lag execution.

Enable selected timing sites ​

Set LoaderConfig::profile to Some(SiteMask::parse(&["io", "cpu", "wait"])? ) when constructing the loader. SiteMask::ALL selects every site.

GroupMain coverage
ioSubmit, reap, I/O wait, request latency
cpuDecode, row admission/gather, map, process
waitFrame, plan, window, and output waits; idle
workerWorker lifetime and its main stages
plannerAccess generation, row/page selection, freezing, and publication
calibrateSites used by cost calibration workflows

Individual names such as decode, process, and wait.gen are also accepted. prof::SITES describes each site's name, record kind, parent, and per-schema detail.

Untimed and timed implementations are compiled together. profile = None selects the untimed implementation. A timed implementation checks the selected site mask; disabled sites avoid clock reads. Instrumentation still changes the workload, so assess its overhead before interpreting performance.

Diagnose a limiting stage ​

A histogram records distributions for selected sites. Nested timing sites can overlap; summing every duration is not a wall-time reconstruction.

Cost model ​

CostModel expresses device request capacity, byte bandwidth, worker physical cores, memory bandwidth, and operation costs in core-seconds. Its output entries follow schema order. Loader::plan_options starts with NVMe default costs based on Loader::cores(); replace them with measurements for your machine and workload.

For a priced window, let R be requests, B storage bytes, C core-seconds, M cached-row memory bytes, and s the non-overlap share:

d=max(R/IOPS,B/BW),c=C/coresT=max(max(d,c)+smin(d,c), M/memory_BW).

This is the current CostModel::seconds model, not measured runtime. service exposes each resource's service time; prices derives marginal costs used by planning decisions. Row gather/admission and process costs must match the actual routes and schema behavior.

to_bytes / from_bytes serialize the binary cost model. Optional serde enables Serde integration for applications that manage structured calibration records. The Rust core does not automatically discover or calibrate your hardware.

API: RunStats, SiteMask, ProfileReport, CostModel.
