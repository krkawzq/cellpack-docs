Access sequences and AccessFn API ​

python
from pycellpack.loader import Accesses, AccessFn
from pycellpack.loader.access_fn import numba_bindings

This Accesses uses native global cell IDs. The training Accesses instead holds corpus dataset/local-row pairs.

len(sequence) counts accesses. For multiple schemas, accesses are ordered position first, schema second; replicate or offset explicitly. Function callbacks may be called out of order or repeatedly.

AccessFn factories ​

from_library, from_source, and from_cfunc return AccessFn. Shared parameters:

ParameterMeaning
lengthRequired nonnegative sequence length
kind"global" (default) emits cell IDs; "corpus" emits dataset IDs and local rows
functionExported C symbol, default generate_accesses for library/source factories
user_dataCallback context pointer or ctypes/NumPy-backed data
key / identityStable configuration key / explicit function identity
ownerAdditional object retaining native parameter/code storage
sources / code / **buildFiles, inline source and compile_library options for from_source

bind(counts=None) returns native Accesses retaining owners. fill(..., counts=...) inspects generated IDs. Corpus functions require counts unless the loader binds them automatically. include_dir() exposes the ABI header; numba_bindings supplies global/corpus signatures lazily.

Callback contract ​

loader.access_fn.AccessFn owns and binds functions from a shared library, C/C++ source or Numba (from_library, from_source, from_cfunc), following ProcessFn's construction and ownership pattern. include_dir() exposes access_fn_cabi.h; the matching core header is crates/cellpack/include/access_fn_cabi.h.

c
typedef int32_t (*CellPackAccessFn)(void *context, uint64_t start,
                                  uint64_t count, uint32_t *cells);
typedef int32_t (*CellPackCorpusAccessFn)(void *context, uint64_t start,
                                        uint64_t count, uint32_t *dataset_ids,
                                        uint64_t *rows);

Bind the first with kind="global" (default) and the second with kind="corpus", giving length separately. Calls fill exactly count entries for [start, start+count), are deterministic and thread-safe, and may repeat or arrive out of order from workers and the online compiler. No borrowed output pointer may escape and no exception may cross the C boundary. A nonzero status fails the run. Corpus ids are translated against dataset view row counts. Per-thread adapter row scratch is outside MemoryEstimate's known reservations. Sampling policy and any seed/epoch configuration are external.

python
from pycellpack.loader.access_fn import AccessFn

access_fn = AccessFn.from_source(
    "sampling.cpp", function="generate_accesses", kind="corpus",
    length=n_samples, user_data=tables, key=table_values, owner=table_arrays,
)
loading = ScDataLoader(corpus=corpus, access_fn=access_fn, ...)

The include path and content cache include the access header and explicitly supplied dependencies. The library, ctypes/NumPy user_data and additional owner are retained. key or explicit identity covers configuration values; pointer addresses are not stable configuration identities. Picklable recipes reconstruct functions after pickle; process-local owners need external reconstruction. numba_bindings() lazily provides GLOBAL_SIGNATURE and CORPUS_SIGNATURE for the same pointer ABI.

ScDataLoader binds corpus row counts automatically. Lower-level Loader start/compile/replay and PageTrace also bind AccessFn to their source's matrix/view counts. bind(counts) returns native Accesses explicitly; fill(..., counts=...) inspects intervals as global cell ids.

The raw-address loader.Accesses.function remains available. loader.Accesses.slice(start, count) composes native intervals without materializing an access function.

AccessFn ​

python
AccessFn(address, context, length, *, kind, identity, owner=None)

A deterministic range function with global or corpus addressing.

kind='global' implements CellPackAccessFn; kind='corpus' implements CellPackCorpusAccessFn and fills dataset ids and local rows. Functions may be called concurrently, repeatedly and out of order by online compilation and loading. A corpus function is bound to row counts by ScDataLoader, or explicitly with bind(counts).
