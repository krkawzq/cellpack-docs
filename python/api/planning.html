PyCellPack/API

Planning API ​

python
from pycellpack.loader.opt import PlanOptions, Plan, PageTrace, CostModel

Create options with loading.plan_options(cache_bytes, cost="auto") to resolve the loader's gap and costs. compile(accesses, options, online=False) accepts a PlanOptions or byte budget and returns Plan. compile_stats returns OnlineStats; replay returns PlanSummary.

PlanOptions parameters ​

FieldDefaultMeaning
cache_bytesRequiredShared page/row cache budget in bytes
gapNoneReuse gap in slots, resolved from loader window
threadsNoneOffline usable CPUs; online quarter of workers; capped at 16
objective"time"Modeled time or "misses" page-miss objective
costNoneCostModel; required for rows and block reads
rowsFalseEnable native-precision row caching
block_pagesNoneMerge adjacent reads in blocks of 2–128 pages
row_policy"incremental"Online-capable incremental decisions or offline "global" reference
horizonNoneOnline lookahead in slots, at least gap
chunkNonePositive online advance in accesses
cpus()Compiler thread CPU affinity

start(plan=None) uses no cache; start(plan=Plan) executes an offline plan; passing options or a byte budget enables online compilation. Plans bind mappings, schemas, slot layout and sequence. Changing those invalidates reuse.

Serialization and interpretation ​

Plan.open/write read and write CPKPLAN1 files; from_bytes/to_bytes support storage and IPC. summary and online_stats contain typed counts, not observed throughput. distance counts accesses; reuse_gap counts slots. residencies returns arrays in admission order.

PageTrace.from_pages or from_source builds a serial page sequence. optimum(capacity_pages) computes the Belady reference, not an optimal mixed row/page plan.

CostModel prices requests, bytes, cores, memory bandwidth and per-output processing. Cost classes expose typed fields/defaults below. save/load serialize JSON; partial records use current defaults for missing fields. No calibration is performed implicitly. See the planning guide.

PlanOptions ​

What a plan is compiled for. gap is the reuse gap in slots (default: the loader's window); runs of the plan execute within a window of at most it, and every residency reserves its frames from that far before its admission. rows caches rows too (page+row; needs a cost model), chosen by row_policy: "incremental" (each reuse decided as it arrives, against a shadow price of capacity learned from the pages) or "global" (rows first over the whole stored sequence; offline only). block_pages merges adjacent admissions into reads of 2 to 128 pages (needs a cost model). horizon bounds, in slots, the reuse intervals an online plan considers (at least gap); chunk is how many accesses the online compiler advances, freezes and publishes at a time. objective minimizes the modeled time ("time", the default) or page misses ("misses"); cost prices the decisions and is required for rows and block_pages.

threads=None resolves when a loader uses the options: offline, one per usable CPU (cpus if pinned); online, a quarter of the loader's workers; both at most 16. cpus pins the compiler threads (empty inherits the calling thread's CPUs).

CostModel ​

The loader's resources on one machine and the work it does (see cellpack::opt::model).

Four resources serve a run: the device's read requests (iops) and bytes (bandwidth), the workers' physical cores (cores) and main memory traffic of cached rows (memory_bandwidth). Work is in core-seconds: per access (access), per read request (request), per access the online compiler takes from the workers' cores (compile, online plans only), decoding (input), cached rows (rows) and each output (outputs, keyed by the loader's output names, or by position; convert adds a per-element cost for each conversion class, CONVERSIONS). A window of bucket accesses takes its device time (the longer of requests and bytes) or its core time, whichever is longer, plus serial of the shorter; a longer memory time overrides that sum. provenance records where each part came from (see pycellpack.loader.costs.resolve); it is not compared. The rates are positive and finite, costs finite and nonnegative, serial in [0, 1], bucket at least 1, and outputs has one entry per loader output; compilation and replay reject a model that breaks this.

to_dict/save write JSON in the native field names (outputs as a list in mapping order, each with its name), which the Rust crate reads with its serde feature.

OutputCost ​

Core-seconds of one output: its process function per call (none for the built-in output), per element mapped to its output dims and written, and per output dim filled with the default (dense rows). A partial call adds resolve per call and resolve_element per stored element; a non-empty curve replaces the fixed process and resolver costs with size bands.

PlanSummary ​

A plan's serial replay: page uses and hits; read requests and bytes; residencies and extra admission reads (block_reads); decoded records, their elements and those in a cold chunk; row hits and admissions with their elements and payload bytes; per schema (in loader order) the elements mapped, rows filled, process and partial calls; elements per conversion class; the most cache bytes held (serially, and reserved from each admission's reuse gap); modeled core-seconds (worker_seconds). Per quarter of the sequence (one epoch of a 4-epoch run): page uses, hits, requests, modeled seconds and each resource's service seconds (requests, bytes, cores, memory: the largest binds). Seconds are zero without a cost model.
