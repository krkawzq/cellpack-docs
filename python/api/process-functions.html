Preset table arguments ​

All factories return ProcessFn with a declared output layout. Tables follow out_ids order. tokens is an integer vector; negative tokens drop dimensions. medians, chroms and starts have the same width as tokens. Presets require float32 mapped input and the declared table width. Build keywords pass to compile_library; a C++17 compiler is required.

The complete factory signatures below list sampling defaults, special tokens and output lengths. Preset field descriptions and callback ABI contracts follow the declarations. See process functions for usage.

ProcessFn ​

A provider-owned pycellpack.process.v1 capsule (see process_fn_cabi.h): a CSR and/or a dense function turning one cell's row, mapped to the schema's output dims and converted to its dtype, into the cell's fixed-size output.

Four ways to build one: ProcessFn.from_source compiles C/C++ code and binds it; ProcessFn.from_cfunc binds numba @cfunc functions (or compiles Python functions as such); ProcessFn.from_library binds the functions of a library built elsewhere (an MSVC DLL, say); the constructor takes a vtable capsule made by hand.

Row semantics: an output dim the cell's matrix has a column for is present (its stored value, or 0 where the record stores none: CSR drops zeros, so they are expression values); an output dim with no matching column is missing; a column no output dim takes is dropped. CSR rows list stored elements only. Dense rows hold 0 at present zeros and the schema's default at missing dims, so a default no value takes (NaN, the dtype's maximum) lets a dense function tell missing dims apart; a CSR function can instead keep each dataset's genes in its user data and find the cell's dataset from the context's global cell id.

row_format picks the rows delivered: "auto" (both functions) gives CSR records as CSR rows; dense records use internal throughput thresholds based on dimensions, dtype conversion, value coding and cache state. Cached dense records may compact to CSR once at admission. "csr" or "dense" always delivers that format and needs only that function (the other vtable entry may be NULL).

The functions are native and thread-safe, write only their cell's output and their scratch (nothing is checked), and must compute the same output from the same row. identity versions the functions and all retained configuration; owner can retain a shared library, vtable or parameters. partial_rows declares that the CSR function resolves rows given without columns and values.

A function built by from_source, by from_library from a library path and exported names, or by from_cfunc from picklable functions pickles as that recipe (the other process rebuilds it, from the build cache for sources); one bound from a hand-made capsule or raw addresses names this process's memory and does not.

ProcessFn.from_library ​

python
ProcessFn.from_library(library, *, csr=None, dense=None, user_data=None, key=None, identity=None, row_format=None, partial_rows=False, owner=None, output=None)

Binds a shared library's process functions, without a hand-made vtable or capsule.

library is a path or a loaded ctypes.CDLL; csr and dense name the exported functions (or give ctypes functions or addresses). The row format defaults to what they cover: both "auto", one alone that format. user_data is passed to every call: a ctypes object (a Structure, an array) or a numpy array, both kept alive, or a raw address the caller keeps valid; owner retains anything else it points to.

The identity defaults to a hash of the library file, the function names, the row format, partial_rows and key, which must describe what user_data holds (numbers, strings, bytes, numpy arrays, ctypes objects, or lists/tuples/dicts of them); give identity instead to set it directly. Raises ProcessLibraryError when the library cannot be loaded or lacks a function.

output is an OutputLayout or structured dtype specification for the function's fixed output record. It enables schema() and unpack() and must agree with the function's actual writes.

ProcessFn.from_cfunc ​

python
ProcessFn.from_cfunc(*, csr=None, dense=None, user_data=None, key=None, identity=None, row_format=None, partial_rows=False, owner=None, output=None)

Binds process functions written in Python with numba.

csr and dense are numba @cfunc functions with the signatures returned by pycellpack.loader.process_fn.numba_bindings() (CSR_SIGNATURE, DENSE_SIGNATURE; int32(voidptr) is accepted too), or plain Python functions, which are compiled with those signatures here. user_data, key, identity, row_format, partial_rows and owner are as for from_library; the default identity hashes the functions' source (or bytecode), the numba version, the row format, partial_rows and key, which must also cover globals or closures the functions read. Raises ProcessBuildError when numba cannot compile a function, TypeError for a cfunc of another signature.

OutputLayout ​

python
OutputLayout(fields, *, align=True)

A NumPy structured dtype describing one native output record.

fields takes NumPy's structured dtype specifications, for example [("ids", "i8", (1024,)), ("length", "u4")]. C struct alignment (including tail padding) is used by default. Explicit offsets and an itemsize can instead be supplied through a NumPy dtype. The declaration must agree with the native function; it does not change the function.

OutputLayout.unpack ​

python
OutputLayout.unpack(raw: np.ndarray, *, copy=False) -> dict[str, np.ndarray]

View uint8[..., row_bytes] as named arrays without copying.

The last axis must be contiguous; preceding axes may be strided. Views retain their source, including a batch's slot lease. Fields may be strided or unaligned. copy=True returns independent, aligned C-contiguous arrays, releasing that dependency. GPU training can instead transfer the complete packed buffer and construct device field views after the H2D copy has completed.

compile_library ​

python
compile_library(sources=(), *, code=None, language=None, name=None, compiler=None, std=None, optimize='-O3', flags=(), include_dirs=(), defines=None, depends=(), cache_dir=None, force=False) -> Path

Compiles process function sources into a shared library; returns its path.

sources are C or C++ files (by suffix); code adds inline source text in language, C++ unless language="c" (one driver invocation compiles every input as one language, so inline code joins C source files only when it is declared C). The process headers (process_fn_cabi.h and the model templates under template/) and every source file's directory are on the include path, before include_dirs. flags are passed to the compiler as is (say ["-march=native"]); defines maps macro names to values (None: defined without a value).

The library is cached under cache_dir (default $CELLPACK_HOME/process-libraries) by everything that shapes it: the compiler and its version, the command options, the sources, the process headers and the files in depends (headers or included sources not listed in sources). A cached library is reused unless force; concurrent builds of the same library are safe. Raises CompilerNotFoundError when no GCC/Clang driver is usable and ProcessBuildError (with the command and the compiler's messages) when compilation fails.

Detailed contracts ​

ProcessFn wraps the pycellpack.process.v1 capsule ABI in loader/process_fn/include/process_fn_cabi.h (also ProcessFn.include_dir()). from_library, from_source and from_cfunc bind exported C functions, compiled C/C++ source or Numba callbacks. compile_library compiles and caches libraries by source, compiler, options, header and dependencies. row_format="auto" requires CSR and dense callbacks with equivalent results; "csr" or "dense" requires only that format. partial_rows=True enables the CSR resolver. Nonzero callbacks fail the run.

Callbacks receive mapped columns and values converted to the schema dtype; they write only their row_bytes and scratch, retain no native pointers and must be thread-safe. identity versions the function and all configuration it reads; key contributes configuration to derived identities. owner keeps native buffers alive. Loader/schema/process objects pickle when their sources and factory recipes do; raw pointers or capsules cannot be sent to another process. Numba is optional and loaded on use (loader.process_fn.numba_bindings()). See the illustrative model example.

Named process outputs ​

process_fn.OutputLayout describes a fixed output record using NumPy structured dtype fields. It uses C struct alignment and tail padding by default; align=False describes packed records. Fields must contain native-endian numeric values. Explicit dtype offsets and itemsize are also supported. The declaration must match the native function's actual writes.

python
from pycellpack.loader.process_fn import OutputLayout, ProcessFn

layout = OutputLayout([("ids", "i8", (1024,)), ("length", "u4")])
# Add output=layout to from_library, from_source or from_cfunc.
process = ProcessFn.from_library("tokenize.so", dense="tokenize_dense", output=layout)
schema = process.schema(out_ids, name="tokens")

process.output holds the layout; row_bytes is its padded record size. process.schema(...) builds an OutputSchema with that size and defaults to float32 mapped input for custom functions. OutputSchema(..., process=process) also infers row_bytes when a layout is declared and rejects an explicitly conflicting size. Opaque functions without a layout keep the explicit row_bytes interface.

process.unpack(batch.region(name)) returns a dict of NumPy field views. The input must be uint8[..., row_bytes] with a contiguous byte axis; leading axes may be strided. Scalar fields have the leading shape, array fields append their declared shape. Views keep the source and its slot lease alive, including after the Batch is released or the Run closes. Fields may be strided or unaligned. copy=True returns independent, aligned C-contiguous arrays when a caller needs to retain CPU data. This helper accepts NumPy host arrays.

For GPU training, retain the single packed NumPy slot view and construct a zero-copy host Tensor with torch.from_numpy. Transfer the complete packed buffer once, then construct field views on the GPU and make only the needed fields contiguous there, using separate CUDA streams when useful. Allocate the output ring over pinned memory to support asynchronous H2D. Wait for the H2D copy's event or copy stream to complete before releasing the Batch and dropping its host Tensor and NumPy view; submitting a nonblocking copy alone does not finish reading the slot. Every additional CPU field view also retains the slot until dropped. Device fields retain device storage only, so their processing can continue after the host slot is reused. The runnable example demonstrates this path with --device cuda, including stream dependencies and allocation lifetimes. CPU inspection uses zero-copy unpack() views.

Python model presets ​

loader.process_fn.presets binds the four supplied C++ templates directly:

python
from pycellpack.loader.process_fn import presets

process = presets.scgpt(tokens, pad_token=0, cls_token=1, length=1024, seed=7)
schema = process.schema(out_ids, name="scgpt")
loading = Loader(source, schema, workers=4, slot_rows=128)
with loading.start(cells) as run:
    for batch in run:
        with batch:
            inspect_fields(process.unpack(batch.region("scgpt")))
    run.join()

This CPU inspection callback must finish using its field views before returning. Use the packed-transfer path above for GPU training.

Tokens and auxiliary tables are indexed by schema output dim, in the same order as out_ids; negative tokens exclude a dim. The caller still owns source gene alignment. Factories copy their inputs and retain all native owners. Their pickle recipes store values, rebuild pointers in the receiver and reuse the compilation cache. Identities cover the code, template parameters and table contents, independently of pointer addresses. row_format="auto", "csr" and "dense" choose input delivery as for other ProcessFns. Compiler keywords go to compile_library; a C++17 compiler is required even when resolving a cached build. Native and Python struct sizes and offsets are checked during compilation.

The defaults and sampling behavior are those of the shipped templates, not inferred from a model checkpoint. Each factory exposes its template's hyperparameters as keywords. input_dtype is float32 and out_dim is the table width; schemas reject incompatible mapped dtypes or widths before loading. STATE SE's batch controls shared query draws over consecutive access positions and must match the intended training microbatch. Cell content restrictions and native status codes still follow each header. See the runnable CPU/CUDA example.

include/template/<model>.hpp holds model presets (scgpt, geneformer, uce, state_se): C++ templates over a parameter struct, because each training configuration needs its own statically compiled functions. A source derives the parameters from the preset's defaults and exports an instance:

cpp
#include "template/scgpt.hpp"
struct Config : pycellpack::preset::ScGptDefaults { static constexpr uint32_t length = 1200; };
PYCELLPACK_EXPORT_PROCESS_FN(scgpt, pycellpack::preset::ScGpt<Config>)

ProcessFn.from_source(code=..., csr="scgpt_csr", dense="scgpt_dense", user_data=tables, key=...) binds it; each header documents its runtime tables (the user_data layout), output layout (out_bytes is the schema's row_bytes) and status codes. template/common.hpp adapts presets to the C ABI.
